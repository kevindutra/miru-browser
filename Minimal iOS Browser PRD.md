Minimal iOS Browser PRD
1. Purpose and Target Users

This minimal web browser is intended for iOS users who prefer not to have a full-featured browser on their phone. The primary use case is viewing single web pages from external sources like QR code menus at restaurants or links received via text messages. It will not allow general web navigation, searches, or direct URL input, focusing solely on a streamlined, view-only experience.

1. Key Features

No Tabs or Bookmarks: The browser will not support multiple tabs, bookmarking, or history storage. Each session opens directly to a linked page and closes without retaining data.

Basic Navigation Only: Includes back, forward, and refresh buttons, with no address bar or search capability.

Single-Page Focus: Opens only to specified links (e.g., from QR codes or text messages) and does not allow manual navigation to other sites.

Built-in Ad Blocking: The browser will include a default ad-blocking feature to provide a cleaner, distraction-free viewing experience.

3. Platform and Tech Stack

Platform: iOS-only for the initial version.

Language/Framework: The preferred approach is native development in Swift, though other mobile frameworks can be considered if needed.

4. Timeline and Development Goals

Timeline: Aiming for a rapid development cycle, with a working prototype ideally within a few weeks, given the minimal feature set.
